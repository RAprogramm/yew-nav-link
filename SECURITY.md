# Security Policy

## Supported Versions

Only the two most recent minor versions receive security updates.

| Version | Supported          |
|---------|--------------------|
| 0.11.x  | :white_check_mark: |
| 0.10.x  | :white_check_mark: |
| < 0.10  | :x:                |

## Reporting a Vulnerability

**Do not open a public issue for security vulnerabilities.**

Report vulnerabilities through one of the following channels:

1. **Email**: andrey.rozanov.vl@gmail.com
2. **GitHub Security Advisories**: [Create a private advisory](https://github.com/RAprogramm/yew-nav-link/security/advisories/new)

Include the following information:

- Description of the vulnerability
- Steps to reproduce
- Potential impact
- Suggested fix (if available)

## Response Timeline

| Stage | Timeline |
|-------|----------|
| Acknowledgment | Within 48 hours |
| Initial assessment | Within 7 days |
| Fix deployment | Depends on severity |

## Disclosure

We follow coordinated disclosure. We will work with reporters to
understand and address the issue before any public disclosure.

## Scope

This policy applies to the `yew-nav-link` crate. For vulnerabilities
in dependencies, report them to the respective maintainers.

## Supply-chain verification

Every GitHub release from 0.10.0 onward ships with two extra artefacts
produced by `.github/workflows/release-attestations.yml`:

- `yew-nav-link-sbom.cdx.json` — a [CycloneDX][cdx] software bill of
  materials enumerating every dependency in the published `.crate`.
- A [SLSA build-provenance][slsa] attestation generated by
  `actions/attest-build-provenance`, signed via Sigstore through the
  workflow's OIDC identity. The attestation covers both the `.crate`
  file and the SBOM.

[cdx]: https://cyclonedx.org/
[slsa]: https://slsa.dev/spec/v1.0/provenance

### Verifying a release

Install the GitHub CLI and the [Sigstore-bundled `gh attestation`][gh]
extension (built into recent `gh` versions), then:

```bash
# Download the published .crate from crates.io and the SBOM from the
# matching GitHub release:
cargo download yew-nav-link --version X.Y.Z --output yew-nav-link.crate
gh release download "vX.Y.Z" --pattern 'yew-nav-link-sbom.cdx.json' \
    --repo RAprogramm/yew-nav-link

# Verify provenance for both artefacts. The attestation references the
# GitHub Actions workflow that built them; verification fails if the
# signature does not chain back to the expected workflow identity.
gh attestation verify yew-nav-link.crate         --repo RAprogramm/yew-nav-link
gh attestation verify yew-nav-link-sbom.cdx.json --repo RAprogramm/yew-nav-link
```

A successful run prints the workflow that produced each artefact and
the commit it was built from.

[gh]: https://docs.github.com/en/actions/security-for-github-actions/using-artifact-attestations/using-artifact-attestations-to-establish-provenance-for-builds
