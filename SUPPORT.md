# Getting help

Pick the right channel for the question you have.

| Channel | Use it for |
|---|---|
| [GitHub Discussions](https://github.com/RAprogramm/yew-nav-link/discussions) | Open-ended "how do I…" questions, design feedback, ideas you are not yet ready to file as an issue. |
| [Bug report](https://github.com/RAprogramm/yew-nav-link/issues/new?template=bug.yml) | Reproducible defects in the published library or the demo. |
| [Feature request](https://github.com/RAprogramm/yew-nav-link/issues/new?template=feature.yml) | New API surface, behaviour changes, ergonomics. |
| [`SECURITY.md`](SECURITY.md) | **Anything that could be a vulnerability.** Do not open a public issue. |
| [docs.rs](https://docs.rs/yew-nav-link) | API reference (rustdoc). |
| [Live demo](https://raprogramm.github.io/yew-nav-link/) | See every public component, hook, and utility wired up. |

Before opening an issue, please:

1. Search [closed issues](https://github.com/RAprogramm/yew-nav-link/issues?q=is%3Aissue+is%3Aclosed) — the answer is often there.
2. Confirm the bug reproduces against the latest published version on
   crates.io (`cargo update`).
3. Reduce to a minimal example. The smaller the repro, the faster the fix.

## Response time

The project is maintained on a best-effort basis. Expect a first response
within a week for most issues. Security reports get priority — see
`SECURITY.md` for the dedicated channel.

## Commercial support

There is no paid support tier. Sponsorships through GitHub Sponsors (see
[`.github/FUNDING.yml`](.github/FUNDING.yml)) help the project move
forward but do not buy preferential treatment for issues.
